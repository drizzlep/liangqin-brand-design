# 良禽品牌体统一调用前置说明

这份说明给 OpenClaw、Hermes 与其他机器人在进入正式生成前快速对齐使用。

它不是新的品牌真源，只是把现有规则压缩成一页调用前置清单。  
所有结论仍以 `foundation-dna/`、`DESIGN.md`、`DESIGN-GOVERNANCE.md` 与相关协议文件为准。
它现在属于高级接入参考：普通设计 agent 默认先读轻量 `DESIGN.md` 即可；只有进入 OpenClaw / Hermes adapter、高保真交付、分发或回归验收时，才需要补读这一页。

## 1. 先判断你在做什么

- 先分清这次是品牌页、产品页、长图、海报、H5、报价卡、演示稿、原型、动效还是独立 HTML。
- 不要把所有任务都套成网页落地页。
- 如果目标只是先收敛方向，先停在结构化 spec 或受控方向比较，不直接冲高保真。

## 2. 先守住良禽，再谈渠道

- 品类变化只改变内容事实与重点。
- 渠道变化只改变信息密度、画幅、交付方式与交互能力。
- 不允许因为“朋友圈、钉钉、H5、海报、PPT”而切换成另一套品牌语言。

## 3. 先检查资产，再决定能不能出成品

- 优先问：有没有品牌规范、logo 文件、色板、产品资料、参考页面或截图。
- 没有用户补充时，优先读取本标准包根层资产与协议，不得凭记忆猜品牌色或标志。
- `良禽品牌体` 默认不自动插入 logo；只有用户明确要求加入 logo、使用真实标志或品牌落款时才读取并放置 logo。
- 用户明确要求加入 logo 但未读取真实 logo 资产时，只允许输出 structured spec、低细节草稿或待补资料清单。
- 不允许拿纯文字品牌名冒充 logo。

## 4. 需求模糊时怎么做

- 先暴露 assumptions、缺口与可用资产。
- 如果要先给方向，只能在良禽已有 `design-packs/` 内推荐 2 到 3 个方向。
- 这些方向必须明确仍然是“同一品牌下的受控变化”，不是第二套品牌系统。

## 5. 信息不足时怎么做

- 可以降级到 structured spec、placeholder、low-detail draft 或 `blocked_pending_assets`。
- 不允许编造产品参数、图像、案例事实、假数字、假标签或假卖点把版面做满。
- 不允许用装饰、图标或情绪词掩盖事实缺口。

## 6. 最低成品标准

只有同时满足下面几项，才可以把结果当最终视觉成品：

- 明显像良禽佳木
- 中文表达完整自然
- 没有 `Pack`、`Page Goal`、`Preview` 等系统说明词泄漏
- logo 没有缺失或被文本替代
- 图标若存在，必须精致统一；做不到就减少或取消

## 7. 最短执行顺序

1. 读 `DESIGN.md`
2. 判断这次是否只是轻量方向生成；如果是，停在 `DESIGN.md` 即可
3. 如果要真实成品、adapter 接入或回归验收，再读本说明
4. 再按需要补读 `artifact-surfaces/`、`assets/brand/`、`design-packs/`、`evaluation/`

补充约束：

- `DESIGN.md` 是默认鸟瞰地图，本页不是普通 agent 的默认负担。
- 如果工具或机器人吃不动本页，就默认只能停在轻量 `DESIGN.md` 消费，不要宣称完成高保真接入。

## 8. 必须停在 spec 的情况

- 没有真实 logo 资产
- 产品事实不足
- 工具无法稳定控制图标工艺
- 不理解当前 artifact surface
- 结果开始泄漏系统说明词
- 方向已经偏成通用模板，而不是良禽表达

## 9. 一句话口诀

先看真源，再做判断；先守住良禽，再适配渠道；宁可停在 spec，也不要自由发挥。
